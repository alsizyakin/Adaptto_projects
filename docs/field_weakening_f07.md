# F07: направленная ошибка напряжения для подстройки ОП

13.11.2026. **Предложение для следующего ручного опыта, в привод не внедрено.**
Принцип обратной связи по компоненте Uq ранее предложен пользователем.
Здесь конкретизированы расчёт целевого Uq по заданному Iq, учёт знака скорости
и подключение к сохранённой проекции состояния F06.
Основание — [четыре прогона F06-T](control_fix_log.md#f06-t).
Код: [fw_voltage_error_q.m](../tools/fw_limiter/fw_voltage_error_q.m).
Проекция и состояние `fw_trim`, ветка FF и внутренние токовые PI остаются
теми же, чтобы проверить именно влияние сигнала ошибки. Это ещё не решение
всей задачи совместного ограничения токов и напряжений.

**Порядок работ уточнён после F06-NFF:** пользователь предложил сначала
отделить вклад FF и найти старую реализацию Uq. [Отключение FF проверено](f06_noff_validation.md)
на шести парных сценариях без перенастройки; часть переходов улучшилась,
часть ухудшилась. [Исторический вариант](field_weakening_uq_history.md)
рассчитывает предел Uq по фактическому Ud, тогда как этот кандидат — по
расчётному Ud для заданного Iq. До ручного внедрения F07 отдельно исследовать
быстродействие и различие этих сигналов. Ни историческая схема, ни текущий
кандидат ещё не проверены в замкнутой дневной конфигурации F06.

**Уточнение по F06-SG2900:** на реальном максимуме 2900 об/мин выявлено
удержание **положительного** предела Ud после смены/снятия момента, в том числе
в номинале. [Новые результаты](f06_starter2900_validation.md) дополняют прежний
опыт с отрицательным Ud. При положительном Ud предложенная ошибка Uq тоже
положительна, хотя Idref уже существенно выше фактического Id; значит,
её стационарный знак сам по себе не гарантирует освобождение диапазона q.
Перед ручным внедрением следует разобрать этот режим и согласование
ограничителей. Кандидат не считать готовым универсальным исправлением;
проверка полного F07 на обоих знаках d-насыщения остаётся обязательной.

## Что показал F06-T

Период исправлен, но при насыщении d функция получает постоянную ошибку
241,33 − 251,49 = −10,16 В и продолжает углублять Id. На 738 рад/с при Ld +20%
получены Idref = −396,39 А, Id ≈ −275,92 А; Iqref = −42 А, Iq ≈ +95,55 А.
Uq ограничено величиной 0,0316 В. Состояние проецируется правильно, но
сама команда подстройки поддерживает потерю управляемости.

При фиксированном Iq стационарный модуль напряжения имеет минимум по Id.
По разные стороны этого минимума направление его изменения различается.
Поэтому безусловное уменьшение Id при избытке модуля напряжения не задаёт
правильного направления коррекции для всех режимов. Дополнительно, модуль
уже ограниченного вектора не показывает, какое напряжение не получил q-регулятор.

## Предлагаемый сигнал

Для текущего измеренного Id и **окончательного задания Iq**, поступающего
в токовый контур, вычислять стационарную потребность по d:

\[
\omega_e=p\omega_m,\qquad
u_{d,*}=R_s i_d-\omega_e\hat L_q i_{q,ref}.
\]

Из оставшегося напряжения выбирать ветвь q со знаком скорости:

\[
u_{q,*}=\operatorname{sgn}_0(\omega_e)
\sqrt{\max(U_{FW}^2-u_{d,*}^2,0)},
\qquad
e_U=\operatorname{sgn}_0(\omega_e)(u_{q,*}-u_{q,f}).
\]

Здесь sgn₀(0) = +1; `u_q,f` — отфильтрованная конечная команда Uq после
ограничителя. В существующий `fw_trim` подаётся **eU в вольтах**; деление
на Ufw, ограничение относительной ошибки, интегрирование и проекция уже есть
внутри него. Повторно нормировать ошибку перед блоком не нужно.

В стационарном уравнении q при фиксированном Iq:

\[
u_q=R_s i_q+\omega_e(\Psi+L_d i_d),\qquad
\frac{\partial[\operatorname{sgn}(\omega_e)u_q]}{\partial i_d}
=|\omega_e|L_d>0.
\]

Это даёт определённое направление воздействия даже при ошибке величины Ld.
Новый расчёт не использует оценку Ld и не делит на чувствительность или скорость.
Это **стационарное обоснование направления**, а не доказательство устойчивости
замкнутого привода: динамика q, фильтр, FF и ограничения остаются в системе.
Выбранная ветвь Uq также требует проверки в рекуперации и при смене скорости.

В расчёт Ud_target нельзя подставлять измеренный Ud вместо потребности
заданного Iq: при нынешнем насыщении это снова даст нулевой остаток по q.
Если Ud_target² > Ufw², выход `budget_exceeded` сигнализирует о недопустимом
стационарном бюджете. Он пока только диагностический; новый freeze им не создаётся.
В такой области одного Id недостаточно, требуется согласованное ограничение Iq.

На **неизменённой записи** в 6,4 с получаются Ud_target = +98,47 В,
Uq_target = +220,33 В и eU ≈ +220,36 В. Направление коррекции меняется
на снятие чрезмерного отрицательного Id. Фактическая реакция привода на этот
новый сигнал ещё не рассчитана. Отдельный прогон с изменённой логикой будет
выполнен после ручного внедрения пользователем.

## Ручное подключение

Ниже сохранена инструкция **первоначального кандидата**. После результатов
SG2900 первым шагом является разбор положительного насыщения d и согласование
ограничителей; инструкция не означает, что одной замены ошибки уже достаточно.

1. Сохранить отдельную версию `_F07`, сохранив `_F06` как контрольную.
2. Добавить MATLAB Function `fw_voltage_error_q`, вставить код из файла выше.
   Для **Rs** и **PolePairs** выбрать **Scope = Parameter, Tunable = off**:
   они уже есть в рабочей области модели. Получатся шесть сигнальных входов.
3. Задать **Update method = Discrete, Sample time = FocDiscrTime**;
   у оболочки в обычном Block Parameters оставить **Sample time = −1**.
4. Подключить сигналы по таблице. Выход 1 нового блока подать на **вход 2
   `fw_trim` вместо Sum11**. Sum11 сохранить для сравнения старой ошибки.
5. Выходы 2 и 3 (`uq_target`, `ud_target`), а также `budget_exceeded`
   вывести на Scope. Сохранить наблюдение Uq, Iq/Iqref, Id/Idref и обоих
   сигналов ошибки. Kψ сначала оставить **2,5** для сравнения одного изменения.
6. После согласования структуры обновить схему и сохранить. Для дневного
   снимка F06 сначала сравнить F06/F07 на `sg2900_hold_nom`, затем
   `sg2900_hold_user` из [проверки реального диапазона](f06_starter2900_validation.md).
   Сохранить положения
   переключателей оценок, параметры и сценарий. Глубокое ОП до 738 рад/с
   проверять отдельной одинаковой матрицей обоих вариантов; ночной F06-T
   с постоянными Ψ/Lq не является прямым эталоном дневной модели с оценщиками.

| Вход | Сигнал | Точка подключения в текущей схеме |
|---|---|---|
| 1 — Ufw | Цель ОП, В | `From65`, тег `Vs_max` |
| 2 — wm | Измеренная механическая скорость, рад/с | `PS-Simulink Converter2`, выход 1; без дополнительного умножения на PolePairs |
| 3 — Id | Измеренный ток d, А | Выход 1 `Bus Selector`, тот же Id, который записывается в контрольном прогоне |
| 4 — Iqref | Окончательное задание q, А | Тег `Iqreq`, например `From19`; не исходный Repeating Sequence |
| 5 — Lq_used | Lq, выбранная для управления, Гн | Тег `Lq_est`, например `From88`; в дневном снимке F06 от 13.11 12:15 это выход оценщика, в ночном F06-T была постоянная |
| 6 — Uq_f | Фильтр конечного Uq, В | Выход `Low-Pass Filter (Discrete or Continuous)6`, вход которого получает Uq |

Названия блоков фильтра и селектора могут переноситься на две строки в Simulink.
`FocDiscrTime` у нового статического блока задаёт период, но не является
аргументом функции. Старый `fw_trim` по-прежнему использует его как Parameter.

## Проверка и дальнейшие границы

[Компонентный тест](../tools/fw_limiter/test_fw_voltage_error_q.m) проверяет
стационарное равновесие и возвращающее направление ошибки при отклонении Id
на ±1 А: оба знака скорости, Iq = −42/+92 А, Ld = 0,8/1/1,2 от номинала.
Отдельно проверяются знак коррекции в зафиксированной точке залипания,
нулевая скорость и диагностический флаг превышения бюджета.
[Протокол](data/control_fixes/f06t_20261113/q_error_component_test.txt).
Тест не включает Simulink-компиляцию нового блока и замкнутую динамику привода.

Критерий опыта — восстановление отрицательного Iq по команде на 738 рад/с,
без ухода Idref на −396 А и без позднего роста тока при снижении скорости.
После этого повторяются оба профиля в номинале/Ld +20% и дополнительный Ld −20%.
Само попадание токов в предел 420 А не заменяет проверки ошибки слежения.

Совместный ограничитель напряжений и anti-windup токовых PI остаются отдельной
обязательной проверкой. Радиальная проекция сохраняет направление полного
запрошенного вектора и отличается от текущего приоритета d;
[формулы DQ Limiter](https://www.mathworks.com/help/mcb/ref/dqlimiter.html).
Если ограничение будет перенесено за PI и развязку, anti-windup должен получать
результат этого ограничения с учётом добавленной компенсации;
[пример MathWorks с feedforward](https://www.mathworks.com/help/simulink/slref/anti-windup-control-using-a-pid-controller.html).
Эти ссылки описывают отдельные механизмы, а не подтверждают устойчивость F07.
