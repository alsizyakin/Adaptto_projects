# Скрипты к `docs/fw_limiter_issues.md`

Прогоны копии `ideal_source_drive_Idff_aug_param.slx` с логированием сигналов, сводные цифры и
рисунки документа. Исходная модель не меняется: каждый прогон работает с копией `aug_<tag>.slx`
в папке результатов.

Нужны MATLAB R2025a, Simulink, Simscape Electrical, Motor Control Blockset.

## Как запустить

Инструкция по ручному внедрению нового блока — [F06](../../docs/field_weakening_f06.md).
Проверка только компонента (каталог должен быть новым):

```matlab
addpath tools/fw_limiter
test_fw_trim_projected('tmp/f06_component_repeat')
test_fw_trim_persistent('tmp/f06_persistent_repeat')
```

Эта проверка не оценивает устойчивость привода. `run_aug` теперь определяет активную
подстройку по первому входу Sum6. Для F06 trim и состояние берутся с MATLAB Function,
добавлены `fw_psi_cmd`, `fw_e_norm`, `fw_inputs` (FF, eU, Ufw, нижний/верхний предел, Kψ).
Старые sens/freeze/reset/`fw_input_gated` сохраняются только как диагностика старой
ветви и не считаются действующими условиями новой подстройки. В F06 61 записанный
сигнал плюс 2 восстановленных напряжения. При извлечении читается явный список
имён; сторонние безымянные логи не превращаются в поля структуры.

Для полной модели F06 использовать отдельную проверку, например:

```matlab
run_f06_check('tmp/f06_saved_repeat', 'f06_ldp20', 'saved', 0.2, ...
    'docs/data/control_fixes/f06_20261112/user_source.slx')
```

`verify_f06_case` проверяет существующие результаты без повторной симуляции.
Фактический такт определяется по временам состояния; проверка не требует равенства
этому такту FocDiscrTime, а явно сохраняет их отношение для выявления рассогласования.
Для замкнутой F06 не использовать старый `verify_baseline`: он ещё описывает
внешний PID и его собственные пределы. Рабочий SLX этими скриптами не меняется.

Из корня репозитория, все сценарии документа (12 прогонов, по 6 одновременно; 25-секундный прогон
~5 мин в Rapid Accelerator):

```bash
tools/fw_limiter/run_parallel.sh 6
```

Отдельные сценарии: `tools/fw_limiter/run_parallel.sh 2 "" ldp20 nomfine`
(пустая строка — папка результатов по умолчанию). Проверка окружения: `... 1 "" smoke`.

То же из MATLAB, последовательно:

```matlab
addpath tools/fw_limiter
s = fwl_scenarios(); for k = find([s.doc]), run_scenario(s(k).tag); end
metrics          % сводка
latch_table      % таблица раздела 2.2
fig_doc          % перезаписывает docs/img/fw_limiter/*.png
```

## Проверка исправлений

Порядок: внести правку в `ideal_source_drive_Idff_aug_param.slx` → прогнать сценарии в отдельную
папку (`run_parallel.sh 6 tmp/fw_fix`) → `metrics('tmp/fw_fix')` и сравнить с приложением
документа по критериям раздела 6. Если правка меняет имена блоков из списка `sig` в `run_aug.m`,
этот список нужно обновить.

## Контрольная база после изменения модуляции

```matlab
addpath tools/fw_limiter
test_fwl_assess
run_baseline('tmp/control_baseline_new')
verify_baseline('tmp/control_baseline_new') % повторная проверка без симуляции
```

`run_baseline` сохраняет `baseline_source.slx`, затем выполняет `nom` и `ldp20`
на отдельных копиях. Каталог должен быть новым: существующая контрольная база
не перезаписывается. Вторым аргументом можно передать ранее сохранённый SLX.
Результаты — полные `aug_*.mat`, фактически запущенные `aug_*.slx` и `summary.json`.
В MAT и JSON записываются SHA-256 исходной и диагностической моделей, параметры,
длительность и факт завершения. Запись результатов может занимать существенно
больше места, чем старые прогоны с прореживанием 10.

Начиная с F05-W в копии модели включены 58 сигналов (в D06 — 57,
в F04 — 51, в F03 — 49, в F02 — 48,
в B00/F01 — 46): токи и задания, исходный запрос Iq,
совместная пара заданий на входе VectorBase, напряжения после ограничения,
выходы PI до/после ограничения, развязка, три интегратора, FF/trim,
чувствительность до/после фильтра и нижнего предела, freeze/reset, конечные duty,
Vdc и действующие пределы. Отдельные `Psi_used` и `Lq_used` снимаются с тегов,
поступающих в управление; `Psi_est` и `Lq_est` сохраняют выходы фильтров оценщиков.
Поэтому при выборе констант вычисленная оценка и выбранный параметр различимы.
`Iq_voltLim_used` снимается с ветви, фактически входящей во второй вход
`Min_smooth_ab`; исходный `Iq_voltLim` остаётся выходом `Divide4` до введённого
пользователем коэффициента. Это позволяет проверить действие запаса в бюджете q.
`Vabs_f` начиная с F04 наблюдает фактический второй вход `Sum11`, поэтому
после перестановки фильтра сохраняет смысл обратной связи ОП. `Vabs_sqrt` —
отдельный выход `Sqrt1`, в F04 это модуль нефильтрованных Ud/Uq. `Uq_limit` —
остаток напряжения q из `VectorBase/UqLimiter`. В F04 новый Gain в ветви d
равен 1: историческое имя `Ulim` пока соответствует и пределу d, и радиусу
общего круга. При испытаниях другого Gain эти величины нужно логировать раздельно.
В D06 добавлены сумма FF/trim `Psi_candidate`, фактический вход I-регулятора
`fw_input_gated`, три причины блокировки `fw_hold_lower/upper/base` и `omega_base`.
Ошибка до разрешения уже записывалась как `dPsi`; она не дублируется вторым именем
на том же выходном порту. `freeze = 1` разрешает интегрирование, `reset` записан отдельно.
В F05-W добавлен `freeze_used` — фактический первый вход `Product1`, наблюдаемый
через отдельную ветвь Gain = 1 и Terminator. Исторический `freeze` сохраняет
выход вычислявшего его блока NOT. После подключения пользователем константы
это разные сигналы. Постоянное разрешение может иметь один отсчёт при t = 0;
это не обрезанный лог. Его значение проверяется вместе с источником в SLX и
полными записями входа, состояния и выхода интегратора. Имена сигналов и
физические выходные порты проверяются на уникальность до запуска.
`Ud_raw/Uq_raw` вычисляются из необрезанного выхода PI
и соответствующей развязки на сетке PI. Это команды до ограничения;
восстановление фактически реализованного напряжения по duty — следующий пункт бэклога.

Метрики используют совместную пару заданий, а для старых логов — удержание
значений на объединённой сетке. Измеренные Id/Iq обязаны иметь одинаковые
временные метки: их максимум не восстанавливается линейной интерполяцией.
Порог задания равен `Is_max` с численным допуском 1 мкА, измеренного тока —
`1.05*Is_max`. Эти проверки рассчитаны на постоянный предел тока в текущих
сценариях; испытания изменяемого Imax потребуют проверки относительно его сигнала.

Ошибка слежения считается по модулю для обеих осей. Эпизод заканчивается
первым отсчётом ниже порога; эпизод на последнем отсчёте отмечается `OPEN`,
даже если ещё не достиг 20 мс. `recoveryObserved` означает только возврат ошибки
ниже 100 А минимум на 20 мс к концу полного прогона при конечных сигналах.
Это **не доказательство выхода из насыщения при прежней скорости**.
Нет маски статической достижимости и переходного окна; большие ошибки здесь
диагностические и сами по себе не называются защёлкой.

Проверка `completed` требует записанного факта достижения StopTime. Для старых
MAT без этих метаданных завершение не считается подтверждённым. Прогоны с
прореживанием помечаются `fullResolution=false` и не подтверждают отсутствие пиков.
`fwl_machine` и графики старого исследования сохраняют исторические параметры;
актуальные пределы новой контрольной базы берутся из рабочей области модели.
Столбец `T@738` в `metrics` выводится как NaN, если в контрольном окне
скорость 738 рад/с не достигалась; наличие этого окна по времени само по себе
не подтверждает нужный режим.

Обзорный график новых логов (Python, NumPy, SciPy, Matplotlib):

```bash
python3 tools/fw_limiter/baseline_figures.py tmp/control_baseline_new tmp/control_baseline_new/baseline.png
```

Сравнение двух проверенных баз — профиля 408 → 204 рад/с и разгона до 738 рад/с
со снижением скорости:

```bash
python3 tools/fw_limiter/baseline_comparison.py tmp/control_baseline_20261110/full tmp/control_baseline_20261110_sweep738/full tmp/control_baseline_20261110_sweep738/comparison.png
```

Рядом с PNG сохраняется JSON с метриками всех четырёх сочетаний профиля и ошибки
параметров. Скрипт проверяет совпадение параметров обеих баз, наличие полных
непрореженных логов и совпадение максимумов с проверенными MATLAB-сводками.
Общий график показывает фактическую скорость, модуль измеренного тока и
абсолютную ошибку Iq. Полная контрольная база описана в
[отчёте](../../docs/control_baseline_20261110.md).

Последующие изменения алгоритма проверяются на обоих профилях: номинал и
Ld +20% для каждого, по 25 с без прореживания. Для такого сравнения используют
копии одной изменённой модели, переключая только профиль скорости; замена
одного нового прогона старым эталоном не проверяет исправление в обоих режимах.

## Журнал исправлений

Ход работы и выводы ведутся в [журнале](../../docs/control_fix_log.md): проблема,
гипотеза, фактическая коррекция, условия проверки, осциллограммы до/после,
численный эффект и оставшиеся ограничения. Рабочую модель изменяет пользователь.
Контрольные скрипты работают с отдельными копиями; прежние эталоны сохраняются.

```matlab
addpath tools/fw_limiter
run_control_check('tmp/fix_next/hold204', 'hold204')
run_control_check('tmp/fix_next/sweep738', 'sweep738')
run_control_check('tmp/fix_next/saved', 'saved')
```

`hold204` выбирает существующий `1-D Lookup Table4`, `sweep738` — `Table2`,
`saved` сохраняет исходное подключение. Меняются только источник скорости
и его ветвь на Scope в тестовой копии. Каждый запуск включает номинал и Ld +20%,
по 25 с без прореживания, затем проверку результатов. Для строго общего снимка
во все вызовы следует передать один и тот же сохранённый SLX третьим аргументом.

Построение сравнения первого исправления с прежними эталонами:

```bash
python3 tools/fw_limiter/fix_figures.py tmp/control_baseline_20261110/full tmp/control_baseline_20261110_sweep738/full tmp/control_fix_f01_20261112 tmp/control_fix_f01_20261112/figures
```

Диагностика D02 без нового запуска Simulink:

```bash
python3 tools/fw_limiter/diagnose_f01.py tmp/control_fix_f01_20261112 tmp/control_d02_20261112
```

Скрипт сохраняет осциллограммы и численные срезы для профилей `sweep738` и `saved`
при Ld +20%. Стационарный расчёт напряжения не включает L·dI/dt и не заменяет
проверку динамики. Подготовленный опыт F02 с фиксированными Psi/Lq описан в журнале;
результаты опыта записываются отдельной записью F02, не заменяя исходную диагностику.

Сравнение F02 с F01 на двух прежних профилях:

```bash
python3 tools/fw_limiter/f02_figures.py tmp/control_fix_f01_20261112 tmp/control_fix_f02_20261112 tmp/control_fix_f02_20261112/figures
```

Проверяется совпадение параметров и профилей, SHA-256 MAT, контрольные максимумы
и постоянство `Psi_used`/`Lq_used`. Колебания измеряются в указанных окнах постоянной
скорости; спектральный максимум в полосе 50–2000 Гц не является доказательством
причины колебаний или устойчивости за пределами этих окон.

Сравнение F03 с F02:

```bash
python3 tools/fw_limiter/f03_figures.py tmp/control_fix_f02_20261112 tmp/control_fix_f03_20261112 tmp/control_fix_f03_20261112/figures
```

Помимо прежних проверок, сопоставляются момент и средний Iq на тех же полках,
проверяется отношение напряженческих бюджетов 0,95. Для номинального F03
показано окно 6,1–7,4 с: рост колебаний начинается раньше первого длинного
превышения порога ошибки q. Для Ld +20% окно выбирается вокруг первой длительной
ошибки q; при её отсутствии используется участок около 6,8 с.

Сравнение F04 с F03 и проверка сохранённого коэффициента d = 1:

```bash
python3 tools/fw_limiter/f04_figures.py tmp/control_fix_f03_20261112 tmp/control_fix_f04_20261112 tmp/control_fix_f04_20261112/figures
```

Проверяются равенство `Vabs_sqrt = hypot(Ud,Uq)`, коэффициент 0,95 в бюджете Iq,
предел d при Gain = 1 и формула остатка напряжения q. Опыт пользователя с
коэффициентом 0,98 этими прогонами не воспроизводится.

Разбор D05 по полным данным F04:

```bash
python3 tools/fw_limiter/diagnose_f04_ld.py tmp/control_fix_f04_20261112 tmp/f04_ld_analysis_20261112
```

Скрипт сохраняет численные срезы обоих профилей при Ld +20% и осциллограмму
начала срыва на 408 → 204. Стационарная потребность напряжения задания считается
по истинным параметрам, без L·dI/dt; ошибка q-развязки выделена отдельно.
Модель не запускается и не изменяется.

Причины переключений в расширенных логах D06:

```bash
python3 tools/fw_limiter/d06_figures.py tmp/control_d06_20261112/full tmp/control_d06_20261112/figures
```

Проверяются тождества разрешения, reset и произведения ошибки на разрешение.
Число фронтов в окне учитывает оба направления и не называется частотой колебаний.
Входные MAT и максимумы сверяются с проверенными MATLAB-сводками.

Проверка сохранённой `_woFreeze` и дополнительного отрицательного отклонения Ld:

```matlab
addpath tools/fw_limiter
source = 'docs/data/control_fixes/f05w_20261112/user_source.slx';
run_control_check('tmp/f05w_repeat/hold204', 'hold204', source)
run_control_check('tmp/f05w_repeat/sweep738', 'saved', source)
run_parameter_check('tmp/f05w_repeat/sweep738_ldm20', 'ldm20', ...
    struct('deltaLd', -.2, 'deltaLq', 0, 'deltaPsi', 0, 'deltaRs', 0), source)
```

```bash
python3 tools/fw_limiter/f05w_figures.py tmp/control_d06_20261112/full tmp/f05w_repeat tmp/f05w_repeat/figures
```

Первые два вызова дают прежние четыре сочетания, третий — только Ld −20% на
сохранённом профиле до 738. Отрицательное отклонение Ld на hold204 этим не
проверяется. `run_parameter_check` требует все четыре поля ошибок и новый
каталог, сверяет фактические параметры сохранённой копии, полноту логов,
SHA-256 и тождества ограниченных напряжений. Прежние эталоны для этого
дополнительного сценария отсутствуют; он не обозначается сравнением до/после.

`f05w_figures` проверяет совпадение профилей/параметров основной матрицы,
постоянство выбранных Psi/Lq, нулевые вход/состояние/выход подстройки и равенство
суммы FF/trim одному FF. Отдельно сохраняются короткие превышения ошибки q,
характеристики полок и срезы стационарной потребности напряжения по истинным
параметрам. Этот расчёт не содержит L·dI/dt и не доказывает динамическую
устойчивость. Критерий непрерывной ошибки >100 А дольше 20 мс не исключает
пачки коротких ошибок и постоянное рассогласование меньшей величины.

Исследование коэффициента при фактическом разрешении интегрирования 1:

```matlab
addpath tools/fw_limiter
source = 'docs/data/control_fixes/f05i_20261112/user_source.slx';
run_gain_check('tmp/gain_repeat/sweep738_k15_ldp20', 'k15_ldp20', 15, .2, 'saved', source)
run_gain_check('tmp/gain_repeat/hold204_k15_ldp20', 'k15_hold_ldp20', 15, .2, 'hold204', source)
```

```bash
python3 tools/fw_limiter/f05i_analysis.py tmp/gain_repeat tmp/gain_repeat/analysis.json
python3 tools/fw_limiter/f05i_figures.py tmp/gain_repeat tmp/control_fix_f05w_20261112 tmp/gain_repeat/figures
```

`run_gain_check` меняет только `PID Controller/I`, профиль (`saved` или `hold204`)
и ошибку Ld машины. Остальные ошибки нулевые. Контроллер должен оставаться
чистым I-регулятором; постоянное разрешение, reset, пределы ±500·Ld, выбранные
Psi/Lq и фактический коэффициент проверяются в запущенной копии. `gain_source.slx`
содержит настройку и профиль, `baseline_source.slx` фиксирует эту основу, а
`aug_<tag>.slx` дополнительно содержит ошибку Ld и наблюдатели. Исходный
пользовательский SLX не сохраняется и не перезаписывается.

Анализ включает только каталоги, в которых завершена проверка настройки
(`gainExperiment` в JSON). Сравнение графиков требует в том числе случай
`saved`, Ld +20%, I = 15 для разбора запуска; остальные серии добавляются
по наличию проверенных данных. Проверяются хеши MAT, токовые сетки, тождество
входа интегратора и dPsi при разрешении 1 и первый шаг Forward Euler:
`x[1] = I·Ts·dPsi[0]`. Выход PID ограничен, поэтому внутреннее состояние
интегратора записывается и анализируется отдельно от Psi_trim.

## F06: проверка до 450 механических рад/с

[Отчёт](../../docs/f06_release450_validation.md) относится к дневному снимку

таблицы сценария и параметры машины на отдельных копиях. Рабочий SLX

```bash
mkdir -p tmp/f06_release450_repeat
```

Можно запускать отдельные индексы `cases.json` в независимых пакетах. Для

согласованная приёмка. Графики включают исходный запрос и окончательное

## F06: отдельное отключение FF

[Отчёт F06-NFF](../../docs/f06_noff_validation.md): шесть парных прогонов
SG2900 при прежнем Kψ = 2,5. `prepare_noff_f06` создаёт новую копию,
вставляет Gain = 0 после `From58` и подаёт его одновременно на `fw_trim`
и `Sum6`. Код и параметры существующего управления сохранены.
Нельзя обнулять только один из этих входов.

Для повторения использовать новый каталог; исходные MAT с FF должны
оставаться в `tmp/f06_sg2900_20261113/` либо быть воспроизведены отдельно.
Каждый случай запускается отдельным процессом MATLAB.

```bash
mkdir -p tmp/f06_noff_repeat

for k in 1 2 3 4 5 6; do
  matlab -batch "addpath('tools/fw_limiter'); run_release450_suite('tmp/f06_noff_repeat','tmp/f06_noff_repeat/noff_source.slx',$k);"
done
MPLCONFIGDIR=tmp/mpl_cache python3 tools/fw_limiter/noff_comparison.py tmp/f06_noff_repeat tmp/f06_sg2900_20261113 tmp/f06_noff_repeat/analysis
MPLCONFIGDIR=tmp/mpl_cache python3 tools/fw_limiter/noff_mechanism_probe.py tmp/f06_noff_repeat tmp/f06_sg2900_20261113 tmp/f06_noff_repeat/analysis
```

`noff_comparison.py` проверяет одинаковые условия пары, фактически нулевой
вход FF и равенство итоговой суммы подстройке, строит полный вид и общий
переход. `noff_mechanism_probe.py` добавляет первый разгон, новый срыв
при 0 → −105 А и числовые точки. Порог сравнения фактической скорости
0,001 рад/с относится только к численным различиям решения при идентичных
заданных таблицах; критерии тока/слежения не изменены.

Сырые логи содержат и прежний расчёт `Psi_d_ff`; он оставлен для наблюдения.
Использованный FF следует брать из `fw_inputs(:,1)`. Эта проверка не
является настройкой обратной связи без FF и не испытывает исторический
Uq-регулятор. [История и подключения](../../docs/field_weakening_uq_history.md).

## F06: аудит компонентов

[F06-C01](../../docs/f06_component_audit.md) использует два разных снимка
autosave: A с частично отключённым FF и B с восстановленным FF и Gain1 = 0,98.
Их результаты не являются чистым сравнением только правок ограничения Iq.

`audit_f06_components.m` читает исходную копию без сохранения, исполняет
извлечённые `lim` и SVPWM, проверяет диапазоны и копирует фактический UqLimiter
в отдельный тестовый стенд. Исходные функции/стенд/результаты сохраняются
в заданном проектном `tmp/`.

`run_aug` определяет активные источники Iqreq/IqLim по тегам; наблюдения не
остаются привязаны к отключённым `Min3`/`Min_smooth_ab`. Добавлены логи границ
ПИ и знаменателей оценщиков. `inspect_f06_model` проверяет, что FF для проекции
и окончательной суммы приходит из одного порта. Стандартный исполнитель
требует согласованных связей. Только явное поле сценария
`expectedFFConnectionsConsistent = false` разрешает воспроизведение
зафиксированного диагностического случая с разрывом.

```bash
mkdir -p tmp/f06_components_repeat
cp docs/data/control_fixes/f06_components_20261113/cases.json docs/data/control_fixes/f06_components_20261113/component_source.slx docs/data/control_fixes/f06_components_20261113/component_source_ff_restored.slx tmp/f06_components_repeat/
matlab -batch "addpath('tools/fw_limiter'); audit_f06_components('tmp/f06_components_repeat/component_source_ff_restored.slx','tmp/f06_components_repeat/component_tests');"
for k in 1 2 3 4; do
  matlab -batch "addpath('tools/fw_limiter'); r='tmp/f06_components_repeat'; s=jsondecode(fileread(fullfile(r,'cases.json'))); run_release450_suite(r,fullfile(r,s($k).sourceSnapshot),$k);"
done
MPLCONFIGDIR=tmp/mpl_cache python3 tools/fw_limiter/components_analysis.py tmp/f06_components_repeat tmp/f06_sg2900_20261113 tmp/f06_components_repeat/analysis
```

Каждый случай запускается отдельным MATLAB-процессом. Для анализа нужны
также исходные парные MAT F06-SG2900. Проверяется не только вычислительная
корректность, но и исполнение межблочных связей: собственная рекуррентность
`fw_trim` может выполняться при неверно подключённом Sum6.
